# DataLens — Report Data Provenance & Cryptographic Audit

## Overview

A core architectural principle of DataLens is **verifiable analytical provenance**. Business reports generated by DataLens are not disconnected snapshots—they maintain a cryptographic audit trail linking directly back to the immutable Parquet storage version and transformation lineage.

---

## 1. Provenance Schema

Every generated report embeds a dedicated Provenance block:

```json
{
  "provenance": {
    "report_id": "rep-7f8e9a2b",
    "run_id": "run-0192a8b3",
    "dataset_id": "ds-9812-sales",
    "version_id": "v1.0.4",

```

---

## 2. Immutability & Verification

1. **Parquet Manifest Hash (`manifest_sha256`)**:
   - Every dataset version in DataLens has an immutable SHA-256 manifest computed at upload/transformation time.
   - The report runner captures this exact hash at the millisecond query execution starts.
2. **Deterministic Reproducibility**:
   - Because Parquet datasets in DataLens are strictly append-only or immutable versions, any historical report run can be reproduced and audited with exact bit-for-bit metric matching.
3. **Auditing & Compliance**:
   - Financial regulators and corporate auditors can inspect the footer of any PDF, DOCX, or XLSX file generated by DataLens to verify whether the source data has been modified since the report was generated.
